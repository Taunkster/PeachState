# 06 — Fallback Plans & Risk Mitigation

## 6.1 Risk matrix

| Risk | Probability | Impact | Mitigation | Recovery time |
|------|-------------|--------|------------|---------------|
| **FortyGuard API fails / unreachable** | Medium | High (Scenes 1–5 need data) | `FIXTURES=1` is the **default** for the whole demo; all screens identical to live. Day-6 fixture set at `data/fixtures/day6/` (24 envelopes + PDF) regenerated by `fg fixtures record`. Optional `LIVE=1` re-run at the end if the network is solid. | 0s (start in fixture mode) |
| **Map tiles fail (CDN blocked, no internet)** | Medium | High (Scenes 1, 3, 5) | Pre-render static PNG maps per scene and swap to `<img>` fallback; or ship `mbtiles` and serve via `leafmap` local tile server. | <1s (auto-detect tile load failure) |
| **Map tiles slow (partial)** | Medium | Low | CartoDB Positron → OSM fallback; tiles are cached after first load; pre-warm browser cache before demo. | 0s (pre-warmed) |
| **Presenter clicks wrong thing** | Medium | Low | Hidden `Ctrl+D` steps scenes; `DemoState` mutations make every scene reachable in 1 keypress. | <1s |
| **Time runs short** | Medium | Medium | Skip Scene 5 (residential/community scale-down); land after Scene 4 KPIs + one-line scale vision. Core field + corridor story stays intact. | — |
| **Audio/video failure (sharing, mic)** | Low | Medium | Pre-recorded Loom of the identical demo; backup laptop; presenter speaks from script regardless of screen. | <30s |
| **Live API call (if shown) hangs** | Low | High | Never show a live call during the timed demo; any live call happens after the timer stops. SDK has timeout + retry. | 0s (by design) |
| **Streamlit process crashes** | Low | High | Run app locally (no cloud dependency); keep the pre-recorded Loom as ultimate fallback. | <60s |
| **API returns no-data for GA coords** | Very Low (GA confirmed covered) | High | Validate key on Fort Valley coords on day 1 (Employee 4's risk list); fixture mode is unaffected regardless. | 0s |

## 6.2 Degraded modes (documented in `data_source.py`)

| Mode | Env var | Behavior |
|------|---------|----------|
| `FIXTURES` | `DATA_SOURCE=fixtures` | Reads `data/fixtures/*.json`. Zero network calls. **Default for demo.** |
| `LIVE` | `DATA_SOURCE=live` | Calls the SDK; caches per `activity_id`; failures raise → app still renders from last cache. |
| `HYBRID` | `DATA_SOURCE=hybrid` | Live call attempted with 8s timeout; on any error, silently falls back to fixtures (no spinner, no error shown). |

## 6.3 Scripted contingency lines (if something visibly glitches)

- **If a widget re-renders:** "That's the app re-fetching the layer — the cache keeps this instant." *(only if unavoidable)*
- **If a chart looks odd:** Don't apologize. Move on: "Let me show you the operation that matters" → `Ctrl+D`.
- **If the whole app freezes:** Say nothing technical. "Give me five seconds and we'll jump straight to the corridor scene" → switch to pre-recorded Loom screen-share.
- **If the API is mentioned as failing:** "Every number you've seen is real API output, cached locally — the demo doesn't depend on the network." *(only if a judge asks)*

## 6.7 Day 7 — `DATA_SOURCE` implemented (7.2)

The 6.2 matrix is now code, not a plan:

- `coolchain/services/fallback.py` resolves `DATA_SOURCE=fixtures|live|hybrid`
  (default `fixtures`), exposes `probe_live()` (SDK health probe with an 8 s
  hard timeout), `hybrid_fetch()`, `health_status()` and the demo-mode guard
  (`STREAMLIT_SERVER_HEADLESS=true`, `STREAMLIT_BROWSER_GATHER_USAGE_STATS=false`).
- `dashboard/data_source.py` wires `resolve_source()` / `mode_info()` and a
  60 s-cached live probe into the loaders — fixtures stay authoritative.
- `GET /health` now returns `{status, data_source, last_live_ok, cache_age_s,
  last_error, live_probe_ms, live_capable, fixtures_ok}` (7.2).
- Tests: `tests/test_day7.py` covers resolution, timeout→fallback, health
  payload, demo-mode flags, EDT labels and WCAG contrast.
